| 项目 | 结论 |

## 2. 角色设定

### 2.1 瞳（主角 · 守藏灵）

- **身份**：镇馆之宝「青铜纵目面具」的同源精灵，面具碎裂时被昭唤醒。
- **外形**：圆头圆身 Q 版；双眼外凸成柱状（纵目）、招风大耳外张、额心一贴金箔面罩；背上斜插一小截神树枯枝；四肢短小。
- **配色**：主体铜绿 `#4A7A66`，暗部 `#283C34`，金只用于面罩、耳饰、树枝节点 `#E3B24B`；统一深色描边。
- **动作**：帧 0 待机（身体微前倾），帧 1 / 帧 2 交替行走（迈腿 + 身体轻晃）。
- **叙事作用**：玩家化身；结局拼合面具＝找回自己，形成闭环。

### 2.2 昭（副角色 · 太阳神鸟）

- **身份**：从青铜神树纹样中苏醒的金乌，负责带路与解说。
- **外形**：铜绿羽身、金喙与翅尖、尾羽展开呈太阳轮状；始终悬停在主角右上方，说话时扇翅。
- **配色**：羽身铜绿为主（避免与金色 UI 撞色），金仅做喙、翅尖、太阳轮尾羽。
- **动作**：帧 0 悬停（翅膀半展），帧 1 扇翅（上抬），帧 2 侧倾（点头/招呼）。
- **叙事作用**：所有剧情文本的讲述者；替代原青花瓷瓶精灵的全部职能。

### 2.3 素材规格（必须遵守，否则会变形）

| 文件 | 帧数 | 单帧像素 | 整图尺寸 | 用途 |
|---|---|---|---|---|
| `public/assets/hero.png` | 3 | 256 × 347 | 768 × 347 | 首页 CSS 动画 + 关卡 Canvas 行走 |
| `public/assets/guide.png` | 3 | 256 × 302 | 768 × 302 | 首页 CSS 动画 |

- 两套素材均要求**透明背景**、横向等距排列、每帧主体位置与基线一致。
- 单帧宽高比必须保持：主角 `256/347 ≈ 0.738`（与 CSS 显示的 `150/203` 一致），副角色 `256/302 ≈ 0.848`（与 CSS 显示的 `150/177` 一致）。
- 若正式出图的三帧对不齐，可退化为**单帧立绘 + 程序化动效**（上下浮动 + 左右翻转），此时需同步修改第 5 节的接入点。

## 3. 剧情全文（可直接使用的成品文案）

### 3.1 引子（首页对话框）

替换 `index.html` 中现有对话框文案，由昭开口：

> 「昨夜子时，镇馆的纵目面具自己裂开了。灵韵散成十七道碎光，落进东莞六个地方。我是从神树纹里醒来的昭，你是守藏灵瞳——去把它们带回来，别让『锈』先找到。」

> 原句「特派员你好！新馆的文物灵韵散落到了东莞各地，请帮我找回它们！」作废。

### 3.2 第二幕 · 六关线索

触发时机：该关三件宝物**全部收齐**时弹出，复用关卡内现有对话框机制（上半「歌谣」、下半「手记」），不需要新 UI 层。

| 关卡（地名） | 歌谣（对话框标题） | 手记（对话框正文） |
|---|---|---|
| 松山湖 | 星落湖心，目望天河 | 捡到第一片眼泡时，栏杆外正过一列地铁。四千年前的人也在抬头看天。 |
| 可园 | 金箔贴面，龙纹守窗 | 满洲窗和夔龙纹叠在一起，我一时分不清哪个更旧。 |
| 虎门炮台 | 利齿向海，戈止风涛 | 炮台的铁与祭坑的铜，隔了三千年，守的是同一片海。 |
| 南社古村 | 耳听风雨，树通九天 | 祠堂梁上的灰比面具还厚，八百年的村子替我们收着四千年的梦。 |
| 东莞国贸 | 高冠刺云，金杖照城 | 在四十二层的玻璃上看见自己，头上像是已经戴着那顶冠。 |
| 东莞博物馆新馆 | 十七归位，面复其光 | 最后一件回来时，展柜里的面具在响——不是碎，是呼吸。 |

线索顺序即关卡推荐顺序；即使玩家跳关，每关文本独立成立，不影响理解。

### 3.3 第三幕 · 镇馆之复

1. **合成动画前 2 秒**：在图层面板压一层锈色剪影（可用半透明 `#8C3327` / 锈褐渐变矩形 + 模糊边缘），字幕：
   > 「锈来了。它想借面具，重新长出自己的脸。」
2. **合成成功**：沿用现有文案「镇馆之宝·青铜纵目面具，已完整复苏！」，其下追加一行：
   > 「十七道碎光归位，特展如期开幕。」
3. **结局字幕**（全屏淡入，3 秒后自动回到大地图或停留）：
   > 「文物不是被收藏，而是被记住。」
   > 「—— 瞳 & 昭」

## 5. 实施步骤

### P0 · 占位（验证阶段）

1. 用脚本在项目目录内生成长宽比正确的纯色剪影占位图，覆盖 `hero.png` / `guide.png`（脚本仅本地临时使用，用完删除，不留在仓库）。
2. 占位图不需要细节，只要满足：透明底、3 帧等距、主体尺寸与基线正确、铜绿主色 + 金色点缀。
3. 启动游戏，检查：首页两个角色的尺寸与站位、关卡内主角大小与行走节奏、角色与暗色背景的对比度、与金色 UI 是否互抢。
4. 经用户确认占位效果后再进入 P1/P2。

### P1 · 文案接入

1. 替换首页引子（4.2）。
2. 按 4.3 给六关补歌谣/手记并修改收齐时的对话内容。
3. 补终章锈色剪影、追加文案与结局字幕（4.4）。
4. `npm run build` 验证类型。

### P2 · 正式出图

1. 按第 6 节提示词生成序列帧，逐帧检查基线、比例、透明底。
2. 覆盖同名文件，**不改任何代码**。
3. 若三帧不齐：改为单帧立绘，同步调整 `src/level.ts` 第 21–24 行 `HERO_FRAME_W/H` 与 `drawLevel()` 的切帧逻辑（改为整图绘制 + 浮动），并简化 CSS `steps(3)`。

### P3 · 收尾

1. 关卡徽记、地图节点、合成粒子等处的三星堆元素与角色形象做一致性检查（纵目、太阳轮、神树）。
2. 检查 `prefers-reduced-motion` 下角色动画是否停止。
3. 全流程回归：首页 → 地图 → 六关 → 新馆合成 → 结算。

## 8. 风险与回退

| 风险 | 应对 |
|---|---|
| AI 生成三帧对不齐、比例漂移 | 退化为单帧立绘 + 浮动/翻转动效（第 5 节 P2.3） |
| 金色角色与金色 UI 撞色 | 角色主体坚持铜绿，金只做小面积点缀 |
| 剧情弹窗与宝物描述争抢同一对话框 | 收齐前维持单件描述，收齐后改为歌谣 + 手记，二者不并存 |
| 玩家先打新馆再补前关 | 每关文本独立成立，不依赖前后顺序；终章文案不做前置校验 |
| 字体/素材体积增长 | 序列帧为 PNG 单图，增量远小于现有场景图，无需额外优化 |

回退方式：`hero.png` / `guide.png` 保留旧文件备份即可一键还原；文案改动集中在 `index.html` 一处与 `level.ts` 数据表，易于定位。
